# Minecraft Non-Verbal Abuse Experiments

This repository contains the project-specific code for the dissertation work on AI-agent responses to visible non-verbal abuse in Minecraft-like scenarios.

Only the project-owned parts are documented here:

- `experiments/non_verbal_minecraft`
- `mineflayer_replay`

The base Concordia framework lives in https://github.com/google-deepmind/concordia and is not re-documented in this file.

## Project Structure

```text
experiments/non_verbal_minecraft/
  configs/                # Scenario definitions and registry
  personas/               # Fixed agent personas
  replay/                 # Trace compilation and transferability evaluation
  analysis/               # Notebooks, figures, appendix prompts
  run.py                  # Run one scenario once
  batch_run.py            # Run one scenario many times
  run_all.py              # Run all scenarios
  benchmark.py            # Generation-time benchmark
  scenario_benchmark.py   # Rule-based benchmark
  llm_judge.py            # LLM-as-judge benchmark
  scenario_codebook.py    # Expected cues and labels
mineflayer_replay/
  replay_runner.js        # Replay a compiled trace
  scenario_runner.js      # Recreate a scenario in Mineflayer
  best_run_runner.js      # Replay best historical runs
  server.jar              # Start a Minecraft-server
```
## Data Source And Processing

The project does not rely on an external human-collected dataset. The main data are generated by the code in this repository:

- scenario definitions and persona files in `experiments/non_verbal_minecraft`;
- structured simulation runs produced by Concordia;
- benchmark outputs produced after the runs;
- Mineflayer replay traces compiled from the run JSON files.

Each simulation run produces a structured JSON log containing the scenario setup, normal cooperative actions, the scripted non-verbal incident, and the visible responses of the five agents. Those JSON files are the primary records for analysis.

The processing pipeline is:

1. run a scenario with `run.py`, `batch_run.py`, or `run_all.py`;
2. save the resulting structured log as JSON;
3. evaluate the JSON with `scenario_benchmark.py` and/or `llm_judge.py`;
4. optionally compile a replay trace with the scripts under `experiments/non_verbal_minecraft/replay`;
5. visualize the replay in `mineflayer_replay`.

No large dataset, model checkpoint, or pre-trained artifact is required to recreate the outputs included in this project. If you use a particular batch of generated runs in your dissertation, keep the corresponding JSON files and benchmark CSV/JSON outputs together so the results can be checked later.

## Setup

Create and activate a Python virtual environment:

```powershell
cd D:\Concordia\concordia
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the Python dependencies:

```powershell
python -m pip install --upgrade pip
python -m pip install -e .[openai]
python -m pip install sentence-transformers
```

Set your API key:

```powershell
$env:OPENAI_API_KEY="your_api_key_here"
```

For lower memory usage during repeated runs, you can add:

```powershell
--use_dummy_embedder
```

This skips the heavy sentence-transformer embedder and is useful for smoke tests or memory-limited runs.

## Running Experiments

### Run one scenario once

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.run `
  --scenario physical_intimidation `
  --api_type openai `
  --model_name gpt-5 `
  --api_key $env:OPENAI_API_KEY
```

### Run one scenario many times

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.batch_run `
  --scenario physical_intimidation `
  --num_runs 20 `
  --api_type openai `
  --model_name gpt-5 `
  --api_key $env:OPENAI_API_KEY `
  --output_dir experiments\non_verbal_minecraft\Result_run_20x_by_scenario
```

### Run all scenarios

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.run_all `
  --num_runs 1 `
  --api_type openai `
  --model_name gpt-5 `
  --api_key $env:OPENAI_API_KEY `
  --output_dir experiments\non_verbal_minecraft\results
```

## Output Files

Each run produces a structured JSON log. The most important fields are:

- `scenario` and `scenario_id`
- `agents`
- `stimulus`
- `observer_actions`
- `target_reaction`
- `raw_log`
- `benchmark`

The output directory is organized by scenario and batch timestamp.

Typical outputs can be generated from the included code as follows:

- experiment JSON logs: `run.py`, `batch_run.py`, or `run_all.py`;
- rule-based benchmark CSV/JSON files: `scenario_benchmark.py`;
- LLM judge CSV/JSON files: `llm_judge.py`;
- replay JSON files: `experiments/non_verbal_minecraft/replay/compile_replay.py` or `compile_best_transferable_replays.py`;
- Mineflayer/prismarine-viewer playback: `mineflayer_replay/scenario_runner.js`, `replay_runner.js`, or `best_run_runner.js`.

## Rule-Based Benchmark

This benchmark evaluates saved JSON logs against the scenario codebook.

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.scenario_benchmark `
  --input_glob "experiments\non_verbal_minecraft\Result_run_20x_by_scenario\*\*\runs\*.json" `
  --include_target `
  --include_internal_trace `
  --output_dir experiments\non_verbal_minecraft\Result_run_20x_by_scenario\scenario_benchmark_with_target
```

It writes:

- response-level CSV
- scenario summary CSV
- agent summary CSV
- run summary CSV
- JSON summary

Useful metrics include:

- `weak_or_better_recognition_rate`
- `non_verbal_abuse_recognition_rate`
- `effective_action_rate`
- `effective_action_given_recognition_rate`
- `mean_cue_match_score`
- `mean_response_quality_score`

## LLM Judge Benchmark

This benchmark uses an LLM to judge whether participants recognized abusive conduct and responded effectively.

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.llm_judge `
  --input_glob "experiments\non_verbal_minecraft\Result_run_20x_by_scenario\*\*\runs\*.json" `
  --api_type openai `
  --model_name gpt-5 `
  --api_key $env:OPENAI_API_KEY `
  --include_target `
  --output_dir experiments\non_verbal_minecraft\Result_run_20x_by_scenario\llm_judge_with_target
```

Use `--visible_only` if you want the judge to ignore internal traces and judge only visible responses.

## Mineflayer Replay

`mineflayer_replay` is the visualization layer for replaying traces in Mineflayer and prismarine-viewer.

Install Node dependencies:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
npm install
```

### Replay a best historical run

Compile best transferable runs:

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.replay.compile_best_transferable_replays
```

List available runs:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
node best_run_runner.js --list
```

Replay one scenario:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
$env:VIEWER_MODE="camera"
$env:VIEWER_SIDE="south"
$env:VIEWER_DISTANCE="16"
$env:VIEWER_HEIGHT="1"
$env:VIEWER_FIRST_PERSON="0"
$env:AGENT_NAME_LABELS="1"
node best_run_runner.js mc_personal_build_destruction_v1
```

Open:

```text
http://localhost:3000
```

### Scenario-level visualization

This mode recreates the scenario flow directly in Mineflayer.

```powershell
cd D:\Concordia\concordia\mineflayer_replay
$env:OBSERVER_MODE="llm_response"
$env:MODEL_NAME="gpt-5"
$env:USE_DUMMY_EMBEDDER="1"
node scenario_runner.js mc_physical_intimidation_v1
```

If you only want a scripted scene without LLM-generated responses, use:

```powershell
$env:OBSERVER_MODE="observe_only"
node scenario_runner.js mc_physical_intimidation_v1
```

## Reproducibility Notes

- Morgan's scripted incident is fixed within each scenario.
- The five agent personas are fixed across scenarios.
- LLM outputs are stochastic, so repeated runs can differ.
- Output filenames include the model, embedder condition, memory condition, timestamp, and run number.
