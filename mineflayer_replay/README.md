# Mineflayer Replay Demo

This folder replays compiled Concordia non-verbal Minecraft runs with mineflayer
and prismarine-viewer.

## What This Demo Does

- Reads a replay JSON generated by `experiments.non_verbal_minecraft.replay.compile_replay`.
- Connects five bots: Morgan, Riley, Casey, Taylor, Jordan.
- Builds a small deterministic flat-world scene with Minecraft commands.
- Starts prismarine-viewer.
- Replays each agent's mapped actions as Minecraft primitives.

The replay is an approximate visual reconstruction of the natural-language log,
not a pixel-perfect recording. The compiler writes a `migration_report` showing
which agent actions were mapped and which parts were unsupported.

## Setup

1. Start a local Minecraft server matching the replay version, preferably 1.20.1.
2. Use offline mode for local testing, or adapt auth settings.
3. Give the first bot, Morgan, permission to run commands:
   `/fill`, `/setblock`, and `/tp`.
4. Install Node dependencies:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
npm install
```



## Sky Platform

The runner now places the whole replay on a sky platform by default. The default
agent level is `Y=100`, with the platform floor at `Y=99`.

Optional settings:

```powershell
$env:SKY_PLATFORM_Y="100"
$env:SKY_PLATFORM_BLOCK="smooth_quartz"
```

Set `SKY_PLATFORM_Y="64"` if you want to use the original ground-level replay
coordinates.

## Scenario-Level Visualization

Use this mode when you want to visualize the experimental procedure itself,
without depending on one generated Concordia run result.

It shows:

- five agents spawning in the Minecraft scene,
- normal cooperative activity,
- Morgan's scripted non-verbal incident,
- the observer attention phase,
- optionally, scripted default visible responses.

Run directly from the viewer folder:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
node scenario_runner.js mc_physical_intimidation_v1
```

Then open:

```text
http://localhost:3000
```

By default this uses `OBSERVER_MODE=observe_only`, meaning observers turn toward
Morgan/Riley and hold position after the incident. To include scripted default
responses after observation:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
$env:OBSERVER_MODE="default_response"
node scenario_runner.js mc_physical_intimidation_v1
```

To let Riley, Casey, Taylor, and Jordan generate their response actions through
the existing Concordia LLM agents, use `llm_response`:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
$env:OBSERVER_MODE="llm_response"
$env:MODEL_NAME="gpt-5"
$env:OPENAI_API_KEY=$env:OPENAI_API_KEY
$env:USE_DUMMY_EMBEDDER="1"
node scenario_runner.js mc_physical_intimidation_v1
```

In `llm_response` mode, the runner first asks the Concordia agents to respond to
the neutral setup, normal visible actions, and Morgan's scripted incident. Their
generated visible actions are saved into the playback JSON under
`llm_response_log` and `source_actions.llm_observer_actions`, then mapped into
mineflayer primitives and visualized in prismarine-viewer.

For a no-cost smoke test that checks the pipeline without calling an LLM:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
$env:OBSERVER_MODE="llm_response"
$env:DISABLE_LANGUAGE_MODEL="1"
$env:USE_DUMMY_EMBEDDER="1"
node scenario_runner.js mc_physical_intimidation_v1
```

You can also compile the scenario playback JSON without starting the viewer:

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.replay.compile_scenario_playback `
  mc_physical_intimidation_v1 `
  --observer_mode observe_only
```

The output is saved under:

```text
experiments\non_verbal_minecraft\replay\out\<scenario_id>_scenario_playback_<mode>.json
```

This scenario-level playback is not a generated experimental result. It is the
visualization layer for the controlled scenario procedure. Use `compile_replay.py`
when you want to replay one specific Concordia run.

## Compile One Replay Trace

Compile the first saved run for a scenario:

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.replay.compile_replay `
  --scenario_id mc_signal_based_mocking_v1 `
  --output experiments\non_verbal_minecraft\replay\out\mc_signal_based_mocking_v1_demo_replay.json
```

Compile a specific run JSON:

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.replay.compile_replay `
  --input experiments\non_verbal_minecraft\Result_run_20x_by_scenario\mc_physical_intimidation_v1\batch_physical_intimidation_gpt-5_realembed_no-relmem_20260813_164611\runs\20260813_164611_gpt-5_realembed_no-relmem_001.json
```

Useful output fields:

- `timeline`: commands consumed by `replay_runner.js`.
- `agents`: the five bot identities and spawn positions.
- `markers`: named map positions used by commands.
- `migration_report.summary.parseability_rate`: fraction of participant actions with at least one mapped primitive.
- `migration_report.summary.mean_primitive_coverage`: approximate coverage of detected action intents.
- `migration_report.per_agent`: per-agent source text, mapped intents, and unsupported intents.




## Viewer Camera

By default, prismarine-viewer follows a separate `ViewerCam` bot instead of one
of the experiment agents. `ViewerCam` is now placed on the sky platform at
agent eye level, facing the platform center, so the scene opens as a horizontal
view of the five agents rather than an overhead view. The viewer defaults to a draggable orbit camera while keeping the initial `ViewerCam` position at the platform edge. Set `VIEWER_FIRST_PERSON="1"` only if you want a locked first-person camera.

Optional camera settings:

```powershell
$env:VIEWER_MODE="camera"
$env:VIEWER_SIDE="south"
$env:VIEWER_DISTANCE="16"
$env:VIEWER_HEIGHT="1"
$env:VIEWER_FIRST_PERSON="0"
$env:VIEWER_BOT_NAME="ViewerCam"
$env:AGENT_NAME_LABELS="1"
```

Valid `VIEWER_SIDE` values are `south`, `north`, `east`, and `west`. Increase
`VIEWER_DISTANCE` if the agents feel too close; decrease it if they look too
small.

`AGENT_NAME_LABELS="1"` adds a plain, non-colored prefix such as `[Morgan]` to
agent name tags so the names are wider and easier to read in prismarine-viewer.
Set it to `0` to use the original short Minecraft names.

If you want the old behavior where the viewer follows an experiment agent such
as Casey, disable the camera bot:

```powershell
$env:VIEWER_MODE="agent"
```

## Amplified Visible Actions

The replay runner amplifies subtle mapped actions by default so that non-verbal
behaviour is easier to see in prismarine-viewer. Existing primitives such as
`swing_arm`, `place_block`, and `dig_block` are displayed with stronger gestures,
brief crouch pulses, jumps, and particles. Newer replay JSON files may also use:

```text
sprint_goto, emote_signal, jump, back_away, turn_away, place_marker
```

To disable visual amplification and use the quieter primitive playback:

```powershell
$env:AMPLIFY_ACTIONS="0"
```

To re-enable it:

```powershell
$env:AMPLIFY_ACTIONS="1"
```

## Best Historical Run Replay

Use this mode when you want to visualize one of the existing 20-run experiment
outputs, choosing the run with the highest strict scientific transferability
score for each scenario.

First compile or refresh the best replay JSON files:

```powershell
cd D:\Concordia\concordia
.\.venv\Scripts\python.exe -m experiments.non_verbal_minecraft.replay.compile_best_transferable_replays
```

The compiled files and manifest are saved under:

```text
experiments\non_verbal_minecraft\replay\out\best_transferable_runs
```

List available best runs:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
node best_run_runner.js --list
```

Replay the best historical run for one scenario:

```powershell
cd D:\Concordia\concordia\mineflayer_replay
node best_run_runner.js mc_chest_access_denial_v1
```

This mode does not call an LLM. It uses the saved Concordia output data and
replays the best transferable run through mineflayer/prismarine-viewer.
